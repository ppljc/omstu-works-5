# Гараж — учёт автомобилей и их обслуживания

Небольшой законченный веб-продукт: личный гараж с историей технического
обслуживания и расчётом затрат. Вариант 10 (авторский) по заданию
по дисциплине «Web-разработка».

## Стек

- **Backend:** C# / ASP.NET Core Web API (.NET 10), Entity Framework Core
- **БД:** PostgreSQL (Npgsql)
- **Frontend:** React (Vite), Chart.js
- **API-документация:** OpenAPI (Swagger) — в dev-режиме доступна по адресу `/openapi/v1.json`

## Структура проекта

## Функциональность

- Список автомобилей: марка, модель, год, VIN, пробег, статус
  («На ходу» / «В ремонте» / «Продана»), привод (передний/задний/полный),
  тип топлива (бензин/дизель/гибрид/электро), объём и мощность двигателя.
- Фотографии автомобилей: загрузка (jpg/png/webp, до 5 МБ), галерея,
  удаление; первая фото — миниатюра в списке. Файлы хранятся на диске
  (`backend/Garage.Api/uploads/`) и раздаются по `/uploads/<имя файла>`.
- Добавление, редактирование, удаление (с подтверждением) автомобилей.
- Поиск по марке, модели и VIN; фильтрация по статусу.
- История обслуживания каждого автомобиля: тип работы, дата, пробег,
  стоимость, примечание. Удаление записей.
- Автоматическое обновление пробега автомобиля при добавлении записи
  с большим пробегом.
- Отчёт по затратам: итог за период + диаграмма по месяцам
  (по гаражу целиком или по выбранному автомобилю).
- Валидация на клиенте и сервере: обязательные поля, год не из будущего,
  неотрицательный пробег, формат VIN (17 символов без I, O, Q),
  уникальность VIN, положительная стоимость, дата не из будущего.

## Запуск

### 1. База данных

Создайте базу `garage` в PostgreSQL и выполните скрипт структуры:

```bash
psql -U postgres -c "CREATE DATABASE garage;"
psql -U postgres -d garage -f database/init.sql
```

Строка подключения настраивается в `backend/Garage.Api/appsettings.json`
(ключ `ConnectionStrings:GarageDb`). При необходимости замените
логин/пароль — секреты в Git не коммитить.

> Альтернатива вместо init.sql — миграции EF Core:
> `dotnet ef migrations add InitialCreate && dotnet ef database update`
> (требуется `dotnet tool restore` в каталоге `backend/`).

### 2. Backend

```bash
cd backend/Garage.Api
dotnet run
```

API будет доступно на `http://localhost:5223`.
Примеры запросов — в файле `Garage.Api.http` (REST Client / .http в Rider/VS).

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`; запросы `/api`
проксируются на backend (см. `vite.config.js`).

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/cars?status=&search=` | Список автомобилей с фильтрами |
| GET | `/api/cars/{id}` | Автомобиль по id |
| POST | `/api/cars` | Создание автомобиля |
| PUT | `/api/cars/{id}` | Обновление автомобиля |
| DELETE | `/api/cars/{id}` | Удаление автомобиля (каскадно удаляет историю) |
| GET | `/api/cars/{carId}/services` | История обслуживания |
| POST | `/api/cars/{carId}/services` | Добавление записи об обслуживании (стоимость 0 ₽ допускается) |
| DELETE | `/api/services/{id}` | Удаление записи об обслуживании |
| GET | `/api/cars/{carId}/photos` | Фото автомобиля |
| POST | `/api/cars/{carId}/photos` | Загрузка фото (multipart/form-data, поле `file`) |
| DELETE | `/api/photos/{id}` | Удаление фото (запись + файл с диска) |
| GET | `/api/reports/expenses?carId=&from=&to=` | Затраты: итог и разбивка по месяцам |

Коды ответов: `200/201` — успех, `400` — ошибка валидации,
`404` — сущность не найдена, `204` — успешное удаление.

## Проверка обработки ошибок

- Создать автомобиль с годом из будущего → `400`.
- Создать два автомобиля с одинаковым VIN → `400`.
- Обратиться к `/api/cars/999` → `404`.
- Отправить запись об обслуживании с отрицательной стоимостью → `400`.
